# ELDA Code and Data Supplement (Anonymous)

ELDA (Endpoint-Level Demand Assignment) generates repair-free gate-level
subcircuits as explicit cells, Liberty input-pin demands, typed driver sources,
per-source assignment budgets, and complete source-to-demand assignments. This
anonymous supplement packages the frozen V6.1 Source--Demand serializer and
parser, the executable production constrained-decoding grammar, structured
validity checks, repair-free Verilog materialization, Yosys read/check, a real
paper-run sample, tests, and compact paper-result audits.

### Release identity

The released method and Python namespace are **ELDA** and `elda`. The retained
identifier `source_net_v61` is the frozen on-disk schema/configuration key used
by the experiments, not the name of a second method. Likewise,
`SourceNetV61Grammar` is the production class name preserved for exact decoder
reproducibility. `AutoGraph` appears only as the name of a comparison baseline
inside frozen paper-result tables; it is not a package namespace, executable
entry point, implementation identity, or prior name of this release.

## Quick start

From the extracted ZIP root:

```bash
conda env create -f environment.yml
conda activate elda-supplement
conda install -c conda-forge yosys=0.51
bash scripts/run_minimal_reproduction.sh
bash scripts/run_tests.sh
python scripts/recompute_paper_audits.py
python scripts/audit_anonymity.py .
```

The reproduction command requires Yosys by default and returns a nonzero code
if a dependency, round trip, negative test, grammar transition, materializer,
Yosys check, or expected-output comparison fails. `--skip-yosys` is available
only for diagnosis and is **not** a complete verification.

An already prepared environment can be used without network access. The run
itself never downloads data or contacts a service. To select executables:

The shell wrappers resolve Python in this order: an explicit `PYTHON_BIN`,
`$CONDA_PREFIX/bin/python` for an active Conda environment, and finally
`python` from `PATH`. This prevents an EDA toolchain's bundled Python from
overriding the activated project environment.

```bash
PYTHON_BIN=/path/to/python YOSYS_BIN=/path/to/yosys \
  bash scripts/run_minimal_reproduction.sh
```

## Reproduction scope

The default command executes, on CPU:

1. dependency and Yosys discovery;
2. raw cell--endpoint graph loading;
3. production V6.1 Source--Demand serialization;
4. production compact-load tokenization and strict parsing;
5. object and graph reconstruction round trips;
6. all seven reported object conditions (`ObjectComplete`, `Pin`, `Cover`,
   `Cap`, `SrcSem`, `Iface`, and `TopologySafe`);
7. seven intentionally corrupted cases, each checked at its expected rule;
8. every token transition through the exact production
   `SourceNetV61Grammar` in `v61_d0_topology_safe` mode;
9. deterministic, zero-repair structural Verilog materialization;
10. Yosys `read_verilog`, `hierarchy -check`, `proc`, `check`, and `stat`;
11. deterministic sample metrics; and
12. byte comparison against outputs produced by an actual reference run.

This smoke test demonstrates implementation behavior. It does not claim to
regenerate the paper's full distributional numbers. Compact paper-result CSVs
are included in `paper_results/`; `scripts/recompute_paper_audits.py` checks
their component and split-count arithmetic. Full candidates, reference graphs,
and checkpoints are not included; see `LIMITATIONS.md`.

## Tested environment

The archive was validated with Python 3.11.14, PyTorch 2.7.0+cu128,
PyTorch Geometric 2.7.0, Transformers 4.57.6, NetworkX 3.6.1, NumPy
1.26.4, PyYAML 6.0.3, pytest 9.1.1, CUDA runtime 12.8 (unused by the
smoke test), and Yosys 0.51+101. The test is CPU-only and needs less than
100 MB of output space. On the validation host it completes in under one
minute; exact timing is intentionally not part of expected outputs.

If Yosys is missing, install the declared version into the environment with
`conda install -c conda-forge yosys=0.51`, or set `YOSYS_BIN` to a compatible
local build. Do not use `--skip-yosys` when reporting a complete pass.

## Inputs and outputs

`data_sample/raw_subcircuit.json` stores node labels, directed cell-to-endpoint
incidences, endpoint roles, pin IDs, and the frozen schema identifier. The
sample is reconstructed from a successful one-shot final paper attempt;
`paper_attempt_payload.json` and `paper_attempt_tokens.pt` preserve that compact
artifact. No private design name is included.

The generated `outputs/` directory contains the canonical Source--Demand
object, token IDs and readable names, reconstructed object, round-trip report,
validity and negative-case reports, a token-by-token constrained-decoding
trace, structural Verilog, raw Yosys log, structured Yosys result, and metrics.
The stable subset is compared byte-for-byte with `expected_outputs/`. The raw
log is retained for inspection but excluded from byte comparison because Yosys
may print build-specific text.

The schema and token layout are described in `data_sample/schema.md`. In short,
the sequence is `SOS`, ordered CELL/DEMAND/SOURCE/SOURCE_LOAD sections, and
`EOS`. `SOS` is supplied as initial context and is not predicted again.

## Executable entries

- `bash scripts/run_minimal_reproduction.sh [--output-dir DIR]`: full smoke
  pipeline and expected-output check.
- `python scripts/run_pipeline.py --update-expected`: maintainer-only command
  used to regenerate expected outputs after an intentional implementation
  change; it must never be used to hide a mismatch.
- `bash scripts/run_tests.sh`: pytest suite, including an independent temporary
  output run.
- `python scripts/recompute_paper_audits.py`: recompute compact component and
  dataset arithmetic from included CSV records.
- `python scripts/audit_anonymity.py .`: reject private paths, identities,
  credential-like strings, caches, and links escaping the archive.
- `python scripts/audit_release_identity.py .`: ensure executable/configuration
  files use the ELDA namespace and confine comparison-method names to result
  records and explanatory documentation.

## Paper metric mapping

- Generation validity/diversity/distribution fidelity:
  `paper_results/table1_graph_quality.csv`.
- Native materializability and repair burden:
  `paper_results/table2_native_materializability_repair_burden.csv` and the E3
  component file.
- Design-level assembly:
  `paper_results/table3_design_level_assembly.csv`, the frozen LCC audit, and
  E4 component files.
- Representation and state-constraint ablations:
  `table4_representation_ablation.csv` and `table5_decoder_ablation.csv`.
- Dataset composition and split/dedup summaries: the corresponding inventory,
  taxonomy, and duplicate-group CSVs.

All generation rates in the paper use 1,024 one-shot attempts. Final
reference-dependent metrics use the 11,390-object train/validation-deduplicated
test reference. The included compact audit verifies arithmetic closure; it
does not hard-code those tables as a substitute for unavailable raw artifacts.

## Training and generation metadata

`configs/paper_training.yaml` records the actual selected run's architecture,
optimizer, schedule, precision, and checkpoint-selection metadata.
`configs/paper_generation.yaml` records one-shot sampling and seed rules.
`configs/decoder_mask_modes.json` is aligned with the included executable
production grammar. The checkpoint and full data loader are omitted rather
than replaced with a scientifically different toy model.

Generation attempt `i` uses seed `20260629 + i`; the training seed is 0. The
smoke pipeline is deterministic and uses no stochastic operation.

## Troubleshooting

- **Missing module:** activate the declared environment and confirm
  `PYTHON_BIN` points to it.
- **Yosys not found:** install it in the environment or set `YOSYS_BIN`.
- **Expected-output mismatch:** inspect the named file in `outputs/`; do not
  regenerate expected outputs unless the change is intentional and audited.
- **Grammar rejection:** verify that tokenizer offsets and pin/cell vocabularies
  match the object before instantiating the grammar.
- **CUDA errors:** the minimal run does not need CUDA; use a CPU PyTorch build
  with the same major/minor version if necessary.
